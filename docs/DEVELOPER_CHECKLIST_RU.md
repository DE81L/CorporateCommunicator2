Вот конкретный чек-лист для разработчика. По каждому пункту — что не так, где копаться и какое действие нужно сделать (без готового кода — только указания).

## 1. Утечки памяти и ресурсы

| Проблема                                          | Где менять (относительный путь)                                                    | Что именно исправить                                                                                                                         |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **`fileStore` и `syncStore` никогда не чистятся** | `server/src/store/messageStore.ts` (или как у тебя называется модуль со `Map`-ами) | • После успешной доставки/чтения сообщения удаляй записи.<br>• Добавь TTL-очистку (setInterval) либо крон-джоб.                              |
| **Слушатели WebSocket остаются висеть**           | `client/src/hooks/useWebSocket.ts`                                                 | • В `useEffect` при `cleanup` сбрасывай `ws.onopen/onmessage/… = null`.<br>• Храни id таймаута, `clearTimeout(reconnectTimerId)` на unmount. |
| **Express-session memory store**                  | `server/src/index.ts` (место, где подключаешь `express-session`)                   | • На prod подключи внешнее хранилище (Redis, SQL).<br>• Либо задай `cookie.maxAge` + `rolling` + `store.prune()` по расписанию.              |

## 2. “Бесконечное переподключение” клиента

| Проблема                                                                        | Где менять                                                         | Что делать                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Клиент залипает в статусе «connecting», если сервер вернул 401/403 на WebSocket | `client/src/hooks/useWebSocket.ts` + `server/src/ws/connection.ts` | **Сервер:** при отказе на апгрейде отправляй кастомный close-code (например, `4401`).<br>**Клиент:** в `onclose/onerror` проверяй код 4401 ⇒ сразу выкидывай пользователя в `logout()` вместо повторных попыток. |
| После 5 неудачных попыток пользователь не видит, что всё сломалось              | `client/src/components/ConnectionStatus.tsx` (или где статус)      | Когда `retriesLeft === 0`, показывай баннер «Связь с сервером потеряна» + кнопку «Переподключиться».                                                                                                             |

## 4. Регистрация

| Проблема                                                                          | Где менять                                                    | Что делать                                                                                                                                                       |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Неверный baseURL → запрос летит на `undefined/api/register`                       | `client/src/pages/AuthPage.tsx`                               | Используй константу `baseURL` при fetch’е.<br>Логично вынести всё на `apiClient`.                                                                                |

## 6. Логирование и общая устойчивость

| Проблема                                     | Где менять                                                                          | Что делать                                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Ошибки на клиенте теряются в `console.error` | Везде, где есть `console.error` (сообщения, heartbeat, P2P)                         | Перенаправляй в централизованный `toast.error()` или Sentry.<br>Показывай юзеру, если действие критичное (не доставлено сообщение). |
| Дублирование API-клиентов                    | `client/src/utils/apiClient.ts` + все компоненты, где используется `fetch` напрямую | Все сетевые вызовы через `apiClient`, убрать прямые `fetch` с baseURL-хардкодом.                                                    |
| Старый файл маршрутов `/auth` дублируется    | `server/src/auth/routes.ts`                                                         | Удали, чтобы не плодить путаницу в эндпоинтах.                                                                                      |

### Что ещё держать в голове

* **File uploads** — переход на `multipart/form-data`, чтобы не тащить base64.
* **Pagination** для истории сообщений вместо полного `refetchHistory()`.
* **HTTPS + cookie.secure** включить на проде.

С таким списком разработчик знает, **какие файлы** потрогать и **какие правки** внести без копипаста готового кода.

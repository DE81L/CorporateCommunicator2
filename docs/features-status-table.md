# Сопоставление заявленных и реализованных функций

Эта таблица отражает расхождения между требованиями, описанными в проектной документации, и фактическим состоянием репозитория.

| № | Заявлено в ПЗ | Что есть в репозитории | Комментарий |
| - | ------------- | ---------------------- | ----------- |
| 1 | **Полноценная интеграция видеоконференций через Jitsi (возможность аудио-/видеозвонков, логирование звонков)** | Используется `lib-jitsi-meet`, кастомный UI `CallModal`, логирование в файл `logs/call-logs.jsonl` | Требует тестирования. |
| 2 | **Push-уведомления через Firebase Cloud Messaging (FCM) и email-оповещения для офлайн-пользователей** | `notifyUser` лишь пересылает сообщение во внутренний WebSocket, внешних сервисов нет. В конфиге Supabase блок `auth.third_party.firebase` отключён (`enabled = false`). Кода SMTP/Nodemailer нет (поиск `smtp`/`nodemailer` пуст). | Заявленная интеграция с FCM и почтой отсутствует; офлайн-уведомления не будут уходить за пределы сервера. |
| 3 | **Работа через единственный Python WebSocket-сервер (Node-WS «не используется») — ранние требования диплома** | В ПЗ снова описан встроенный WS-сервер Node (`ws`) и только *fallback* к Python при `NO_NODE_WS`, а в коде Node-сервер WebSocket действительно запускается если переменная **не** задана. | Формулировка в ПЗ противоречит прежнему ограничению «без Node WS». Фактически Node-WS активен по-умолчанию. |
| 4 | **FCM-push при офлайн-доставке в `sendChatMessage`** (описано как «делает HTTP-запрос» к Python WS и, если офлайн, вызывает `notifyUser` для FCM) | Функция `sendChatMessage` действительно делает HTTP POST на Python WS, но **не** вызывает никакого внешнего пуш-сервиса — тот же `notifyUser` остаётся stub’ом, см. пункт 2. | Документация обещает FCM-push, но в коде этого нет. |
| 5 | **E-mail уведомления о пропущенных сообщениях** | В репозитории отсутствуют зависимости (`nodemailer`, `smtp-transport` и т.д.) и любой код отправки почты. | Заявленная функциональность не реализована. |
| 6 | **Страница настроек профиля с возможностью менять аватар** | В коде есть только компонент `Header` с выводом аватара и кнопкой уведомлений; раздел `/settings` как страница отсутствует (поиск `SettingsSection`/`settings-page` ничего не нашёл). | Раздел настроек заявлен, но не реализован. |
| 7 | **«Wiki» как готовый модуль совместной работы** (отдельное древовидное меню, markdown-редактор) | Бэкенд-роуты и таблицы для Wiki реализованы, клиентские хуки/страницы есть, однако в интерфейсе отрисовывается заглушка «This feature is temporarily unavailable». | Модуль частично реализован на сервере, но отключён на клиенте. |
| 8 | **Уведомления Toast о новых событиях** (заявлены) | Клиентский Toast-провайдер присутствует и используется, но сервер не формирует явные push-payload’ы, см. п.п. 2-4. | Внутри приложения всплывающие окна работают, но внешние уведомления — нет. |

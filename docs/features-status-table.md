# Сопоставление заявленных и реализованных функций

Эта таблица отражает расхождения между требованиями, описанными в проектной документации, и фактическим состоянием репозитория.

| № | Заявлено в ПЗ | Что есть в репозитории | Комментарий |
| - | ------------- | ---------------------- | ----------- |

| 1 | **Полноценная интеграция видеоконференций через Jitsi (возможность аудио-/видеозвонков, логирование звонков)** | Используется `lib-jitsi-meet`, кастомный UI `CallModal`, логирование в файл `logs/call-logs.jsonl` | Требует тестирования. |
| 2 | **Push-уведомления через Firebase Cloud Messaging (FCM) и email-оповещения для офлайн-пользователей** | Реализован `notifyUser` с отправкой через FCM и запасным E-mail. Токены хранятся в таблице `push_tokens`. | Требуется настроить `FCM_SERVER_KEY` и SMTP параметры. |
| 3 | **Работа через единственный Python WebSocket-сервер (Node-WS «не используется») — ранние требования диплома** | В ПЗ снова описан встроенный WS-сервер Node (`ws`) и только *fallback* к Python при `NO_NODE_WS`, а в коде Node-сервер WebSocket действительно запускается если переменная **не** задана. | Формулировка в ПЗ противоречит прежнему ограничению «без Node WS». Фактически Node-WS активен по-умолчанию. |
| 4 | **FCM-push при офлайн-доставке в `sendChatMessage`** (описано как «делает HTTP-запрос» к Python WS и, если офлайн, вызывает `notifyUser` для FCM) | `sendChatMessage` вызывает `notifyUser`, который теперь использует FCM и email. | Проверить доставку уведомлений. |
| 5 | **E-mail уведомления о пропущенных сообщениях** | Добавлена функция `sendMail` на базе `nodemailer`; используется в `notifyUser`. | Требует конфигурации SMTP. |
| 2 | **Push-уведомления через Firebase Cloud Messaging (FCM) и email-оповещения для офлайн-пользователей** | `notifyUser` лишь пересылает сообщение во внутренний WebSocket, внешних сервисов нет. В конфиге Supabase блок `auth.third_party.firebase` отключён (`enabled = false`). Добавлен модуль `mail.ts` для отправки почты через Gmail, но он нигде не вызывается. | Заявленная интеграция с FCM и почтой по-прежнему отсутствует. |

| 2 | **Push-уведомления через Firebase Cloud Messaging (FCM) и email-оповещения для офлайн-пользователей** | `notifyUser` лишь пересылает сообщение во внутренний WebSocket, внешних сервисов нет. Кода SMTP/Nodemailer нет (поиск `smtp`/`nodemailer` пуст). | Заявленная интеграция с FCM и почтой отсутствует; офлайн-уведомления не будут уходить за пределы сервера. |
| 3 | **Работа через единственный Python WebSocket-сервер (Node-WS «не используется») — ранние требования диплома** | Встроенный `ws` присутствует, но теперь отключён по умолчанию (`USE_NODE_WS=1` включает). | 4 | **FCM-push при офлайн-доставке в `sendChatMessage`** (описано как «делает HTTP-запрос» к Python WS и, если офлайн, вызывает `notifyUser` для FCM) | Функция `sendChatMessage` действительно делает HTTP POST на Python WS, но **не** вызывает никакого внешнего пуш-сервиса — тот же `notifyUser` остаётся stub’ом, см. пункт 2. | Документация обещает FCM-push, но в коде этого нет. |
